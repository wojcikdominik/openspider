Release candidate for 1.0: fixes from the beta.4 feedback and separate connections per host for faster crawls on lossy networks.

- Connections per host: OpenSpider now opens several connections to a host and spreads the requests across them. Before, all threads shared a single connection under HTTP/2, so one lost packet held up every request. The number of simultaneous requests and the URL rate stay the same; the server does not receive more requests than before. The new setting is under Configuration › Speed › "Connections per host": "auto" (default) uses as many connections as threads, at most 6; a fixed value from 1 to 6 sets the limit, and 1 restores the previous behaviour under HTTP/2. If a server refuses an additional connection, the crawl continues on the existing ones without error rows. Under HTTP/1.1 a host receives at most as many simultaneous requests as it has connections, so at most 6 with "auto". The debug info names the value of the crawl.
- Live crawl table: when the table has to reload its data during a fast crawl, it now does so silently. The rows stay visible until the new data has arrived, and the multiple selection, the anchor of a Shift selection and the scroll position are kept. Before, the table could show empty rows, lose the selection or jump to the top. A Shift+click that is under way during such a reload is completed instead of being dropped.
- Live crawl counters: a table opened while the crawl is writing no longer stays behind permanently (for example "18 of 20"). The status no longer shows a finished crawl while the counters are still running.
- Starting a new crawl in the same view keeps the old rows until the new ones arrive, without a loading bar.
- Enter and "Start" respond right after a short crawl has finished. Before, the start command could stay blocked while the start URL was being saved to the suggestion list. The question "Replace" keeps its default action.
- "Recently opened": different spellings of the path of one crawl file are merged into one entry; duplicate entries from beta.4 disappear when the list is loaded. Entries show name or domain and date even if the remembered path is spelled differently from the stored one. This fixes the known issue from beta.4 with crawl storage locations behind a symbolic link.
- "Clear" releases the crawl file completely. On Windows the file could not be deleted, moved or replaced until OpenSpider was closed.
- Crawl management shows start time, duration, number of URLs and size in the format of the UI language.
- Status bar: every Crawl-delay hint from a robots.txt appears only once.
- Security update: rustix 1.1.6 (RUSTSEC-2026-0486).

### Deutsch

Release-Kandidat für 1.0: Korrekturen aus den Rückmeldungen zu beta.4 und getrennte Verbindungen pro Host für schnellere Crawls in Netzen mit Paketverlust.

- Verbindungen pro Host: OpenSpider öffnet jetzt mehrere Verbindungen zu einem Host und verteilt die Anfragen darauf. Bisher teilten sich unter HTTP/2 alle Threads eine einzige Verbindung, sodass ein verlorenes Paket alle Anfragen aufhielt. Die Zahl der gleichzeitigen Anfragen und die URL-Rate bleiben gleich; der Server erhält nicht mehr Anfragen als bisher. Die neue Einstellung steht unter Konfiguration › Geschwindigkeit › „Verbindungen pro Host“: „auto“ (Standard) nutzt so viele Verbindungen wie Threads, höchstens 6; ein fester Wert von 1 bis 6 setzt die Grenze, 1 stellt das bisherige Verhalten unter HTTP/2 wieder her. Lehnt ein Server eine zusätzliche Verbindung ab, läuft der Crawl ohne Fehlerzeilen über die bestehenden weiter. Unter HTTP/1.1 erhält ein Host höchstens so viele gleichzeitige Anfragen, wie er Verbindungen hat, bei „auto“ also höchstens 6. Die Debug-Info nennt den Wert des Crawls.
- Tabelle im Live-Crawl: Muss die Tabelle ihre Daten während eines schnellen Crawls neu laden, geschieht das jetzt still. Die Zeilen bleiben sichtbar, bis die neuen Daten da sind, und Mehrfachauswahl, Anker einer Umschalt-Auswahl und Scrollposition bleiben erhalten. Bisher konnte die Tabelle leere Zeilen zeigen, die Auswahl verlieren oder an den Anfang springen. Ein Umschalt+Klick, der während eines solchen Nachladens läuft, wird abgeschlossen statt verworfen.
- Zähler im Live-Crawl: Eine Tabelle, die geöffnet wird, während der Crawl schreibt, bleibt nicht mehr dauerhaft zurück (zum Beispiel „18 von 20“). Der Status zeigt keinen fertigen Crawl mehr, solange die Zähler noch laufen.
- Ein neuer Crawl in derselben Ansicht behält die alten Zeilen, bis die neuen da sind, ohne Ladebalken.
- Enter und „Start“ reagieren direkt nach dem Ende eines kurzen Crawls. Bisher konnte der Startbefehl gesperrt bleiben, während die Start-URL in die Vorschlagsliste gespeichert wurde. Die Rückfrage „Ersetzen“ behält ihre Standardaktion.
- „Zuletzt geöffnet“: Verschiedene Schreibweisen des Pfads einer Crawl-Datei werden zu einem Eintrag zusammengeführt; Doppeleinträge aus beta.4 verschwinden beim Laden der Liste. Einträge zeigen Name oder Domain und Datum auch dann, wenn der gemerkte Pfad anders geschrieben ist als der gespeicherte. Das behebt den bekannten Fehler aus beta.4 bei Crawl-Speicherorten hinter einer symbolischen Verknüpfung.
- „Löschen“ gibt die Crawl-Datei vollständig frei. Unter Windows ließ sich die Datei bisher nicht löschen, verschieben oder ersetzen, bis OpenSpider beendet wurde.
- Die Crawl-Verwaltung zeigt Startzeit, Dauer, Zahl der URLs und Größe im Format der Oberflächensprache.
- Statusleiste: Jeder Crawl-delay-Hinweis aus einer robots.txt erscheint nur einmal.
- Sicherheits-Update: rustix 1.1.6 (RUSTSEC-2026-0486).
