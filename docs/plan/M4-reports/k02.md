## Öffentliche Schnittstelle (für K04, K07, D01)

```rust
// Konto und HTTP (beide Adapter teilen OpenAiHttp bzw. denselben Arc<OpenAiAccount>)
let account = OpenAiAccount::new();
let http = OpenAiHttp::new(client /* Host-Überschreibung, Proxy */, OpenAiConfig::new(ApiKey::new(key))
    .with_base_url(base /* K07: global oder EU */).with_organization(..).with_project(..), account.clone())
    .with_limiter(limiter.clone()); // nur für AiProvider::execute/models nötig; run/decide melden Header an ihren Limiter
// Responses
let responses = OpenAiResponses::new(http.clone()).with_capabilities(catalog_lookup /* K04 */);
let run: StructuredRun<RequestMeta, RequestFailure> =
    responses.run_structured(&limiter, &request, &schema, repairs, estimated_input_tokens).await;
// je run.requests[i]: meta.request_outcome(status, est_in, est_out, images) → cost::request_record(..)
// Decisions
let decisions = OpenAiDecisions::new(http).with_capabilities(catalog_lookup);
let run: DecisionsRun = decisions.decide(&limiter, &DecisionInput::text(..), &questions,
    &DecideOptions { model, max_questions: MaxQuestionsPerRequest::new(n)?, image_token_estimate }).await;
// run.results: (name, QuestionResult) in Fragenreihenfolge; QuestionResult::status() nach AI-020
// run.requests: DecisionsRequestRecord → request_outcome() → cost::request_record(.., &decisions_billing_rates(&rates), ..)
```

- `QuestionResult::{Answered(DecisionAnswer), Refusal{reason}, MissingAnswer, InvalidOutput{detail}, NotAnswered{status}}`.
- `DecisionAnswer::{Predicate{probability}, Choice{choice, probabilities, confidence, confidence_raw}, Score{score, level_index, level, probabilities, confidence, confidence_raw}}`; `confidence_mismatch()`.
- Kontingent: `OpenAiAccount::quota_stop()` (`error_code` z. B. `credit_balance_exhausted`), `clear_quota_stop()`.
- Fähigkeiten: `RESPONSES_CAPABILITIES`, `DECISIONS_CAPABILITIES`; ohne Katalog meldet `models()` jedes Modell ohne Fähigkeiten (konservativ, Katalog liefert K04).
- Konstanten: `PROVIDER_ID = "openai"`, `DEFAULT_BASE_URL = "https://api.openai.com/v1"`, Endpunkte `"responses"`/`"decisions"`, `DEFAULT_MODEL = "gpt-6-luna"`, `MAX_IMAGE_BYTES`.

## Auslegungen (bitte bestätigen)

1. **20 MB** = 20 × 1024 × 1024 Byte dekodierte Bildgröße; genau 20 MB ist zulässig, ein Byte mehr nicht. Geprüft schon über `Content-Length` und beim Empfang (kein unbegrenzter Download).
2. **Bildformate:** nur PNG, JPEG, WebP, GIF (Erkennung aus den Bytes, sonst `Content-Type`); andere (z. B. SVG der Fixture-Site) → `Skipped (unsupported format)`. AI-004 nennt keine Formatliste.
3. **`input` der Decisions API:** reiner Text als Zeichenkette, mit Bildern als `[{"role": "user", "content": [{"type": "input_text", "text"}, {"type": "input_image", "image_url": "data:…"}]}]` – Feldname `image_url` wie bei Responses; die Spec nennt nur die Teiltypen.
4. **Refusal-Grund (Decisions):** aus `refusal` bzw. `reason`, falls Text (Felder über `name`/`type` hinaus sind nach V-A1 offen).
5. **Wertprüfung (Decisions):** Wahrscheinlichkeiten müssen in [0, 1] liegen, `choice` muss ein angefragter Wert sein, `score` in [0, Levels − 1], Antworttyp muss zum Fragetyp passen – sonst `Error: Invalid output` für diese Frage. Eine Summe ≠ 1 wird **nicht** normiert (AI-033, D01). Fehlt `confidence`, gibt es keinen Mismatch-Vermerk.
6. **Protokollstatus eines Decisions-Requests:** `Success` bei lesbarer Antwort (Status je Frage in den Ergebnissen), `Error: Invalid output` bei unlesbarer Antwort, sonst Endstatus des Requests. `confidence_mismatch` der Zeile = irgendeine Frage des Requests.
7. **Decisions-Abrechnung:** `decisions_billing_rates` setzt den Ausgabepreis 0 und bepreist Cache-Lesen/-Schreiben wie Eingabe („keine Kosten für Cache-Lesen“ als „kein gesonderter Preis“ gelesen); Langkontext-Faktor, Gebühren, Regionalzuschlag unverändert.
8. **Token-Schätzung Decisions** (TPM, Kosten ohne `usage`): ⌈Zeichen/3,5⌉ über Eingabetext **und** alle gesendeten Fragentexte (`name`, `instructions`, `choices`, `levels`) + Bild-Schätzwert; Ausgabe-Schätzung 0.
9. **Responses `status = incomplete`** (z. B. `max_output_tokens`) wird nie teilweise übernommen (wie AI-002 bei `max_tokens`), sondern als unlesbar gewertet (Reparaturversuch, dann `Error: Invalid output`).
10. **Aufwand (`effort`) und `store`** werden für Responses nicht gesendet – AI-003 nennt beides nicht.
11. **Kontingentsperre** gilt für das Konto-Objekt (`OpenAiAccount`), bis der Aufrufer `clear_quota_stop()` aufruft; Lebensdauer (je Lauf/je App-Sitzung) legt D01/U01 fest. Gesperrte Einträge haben `HTTP Status` leer und `Error Code` = Grund des auslösenden Requests.
12. **`AiProvider::execute` (Decisions):** nicht lesbare Fragendefinition → `Error: Invalid output` ohne Request (keine passendere Fehlerklasse in `ProviderError`); `content = {"answers": [{name, status, answer|refusal_reason|detail}]}`; `refusal = true` nur, wenn alle Fragen verweigert wurden.
